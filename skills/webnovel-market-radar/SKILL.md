# 网文与 AI 短剧市场扫榜雷达（短篇 + 长篇 + AI 短剧三轨版）

将市场榜单的实时样本转化为**可验证、带风险边界、可直接交接给写作端**的选题决策。短篇与长篇共用一套标准化采集与质检管线，按体量自动切换分析维度与下游接口。

## 核心纪律（防幻觉、合规与原创底线）

1. **跨样本才算信号**：单本上榜只记为个例；同题材、同情绪或同钩子在多个样本/多个榜单反复出现，才能标为趋势候选。
2. **质量门硬约束**：常规平台有效样本 < 15 条（小平台或细分榜 < 10 条）必须标 `[数据稀疏]`；无实时采集数据时标 `[内置参考降级]`。凡命中这两类标记，对应选题的**可行性严禁标「高」**（最高为「中」，并列出低成本验证动作）。
3. **人机协同与验证合规**：使用浏览器采集时，若遇到**登录页、付费墙、滑动验证码或反爬校验**，立即暂停并请用户在可见浏览器中亲自完成，**严禁尝试破解、绕过或伪造访问权限**。
4. **只采公开元数据，绝不洗稿**：仅收集榜单/公开详情页的排名、书名、作者、标签、字数、热度/在读/收藏及截断简介（≤120 字）；**绝不整篇抓取收费正文**，下游写作只消费抽象情绪骨架与差异化切口，强制原创脑洞置换。

## 赛道路由与工作模式

先向用户明确或从指令识别两项参数：
- **体量赛道 (`--track`)**：
  - `short`：短篇网文赛道（0.8–5 万字，聚焦**情绪交付、完读率、开头钩子、标题/导语公式与反转传播**；建议 2–4 周复扫）。
  - `long`：长篇网文赛道（30 万字+连载，聚焦**题材分布、金手指翻新、在读/追读/订阅/收藏指标与长线可持续性**；建议 1–2 月复扫）。
  - `ai-drama`：AI 短剧 / AI 漫剧 / 沙雕短剧赛道（聚焦**短剧创作者中心官方供需榜 × 飙升榜蓝海缺口、红果 AI 剧/漫剧热播榜与新剧榜、视觉形态分化、季播集数、高赞热评爽雷点与平台激励公告**；建议 2 周复扫）。
  - `both`：跨体量对比（同时观察短/长篇网文风口或网文→AI短剧改编领先信号）。
- **目标平台**：番茄（短故事 / 男女频长篇榜）、红果短剧（`hongguoduanju.com` AI剧/漫剧/总榜）、抖音短剧创作者中心（`shortdramas.com` 题材供需/飙升/抖音热播榜）、知乎盐言、起点、七猫、点众、黑岩、晋江、刺猬猫。

## 四级数据采集策略（浏览器手动模拟优先）

详见 [browser-collection-guide.md](references/browser-collection-guide.md)，按以下优先级获取样本，告别脆弱的硬编码爬虫脚本：

| 优先级 | 采集方式 | 执行策略 |
|---|---|---|
| **1（首选）** | **Ego Browser（`ego-browser`）** | 先检查本机是否可用 `ego-browser`；可用时**先执行 `ego-browser skill`** 按当版指南操作可视化浏览器打开榜单、滚动加载、逐条查看公开详情页提取字段；遇登录/验证码直接请用户在浏览器内接管。 |
| **2（回退）** | **内置浏览器控制（`browser` 子代理）** | 本机未安装 Ego Browser 或用户要求使用内置浏览器时，直接委派 `browser` 子代理打开目标榜单页面，手动模拟点击、切换频道 Tab、滚动加载与读取公开榜单信息。 |
| **3（直读/辅采）** | **用户投喂 / 公开网页检索** | 用户直接粘贴榜单文字、截图、链接或已有扫描 Markdown 时直接解析入库；公开资料不足时可用 `search_web` 辅助核查近期公开榜单讨论与热词。 |
| **4（兜底）** | **内置市场基线参考** | 无法联网且无用户样本时，读取 [platform-baselines.md](references/platform-baselines.md) 输出候选假设，**必须显式标注 `[内置参考降级]`，可行性封顶「中」**并列出待人工复扫页面。 |

## 四步标准工作流

### 1. 初始化本次扫榜目录

每次扫榜沉淀到独立目录（默认 `扫榜/{YYYYMMDD}_{平台}_{short|long|ai-drama|both}/`），生成标准骨架：

```text
python <skill-dir>/scripts/init_scan_session.py --root <项目根或工作区> --platform <平台名> --track <short|long|ai-drama|both> --source-mode <ego-browser|builtin-browser|user-input|baseline>
```

### 2. 采榜与样本清洗

读 [browser-collection-guide.md](references/browser-collection-guide.md) 执行采集与清洗：
- 移除平台模板废话（如“免费在线阅读全文”等），公开简介超过 120 字在自然句末截断加 `...`，缺失字段统一标 `[待补]`。
- 在 `扫榜报告.md` 文件头如实填写：抓取日期、来源 URL、采集方式、有效条目数与数据质量状态（`[OK]` / `[数据稀疏]` / `[内置参考降级]`）。

### 3. 提炼模式与输出「扫榜报告 + 选题简报」

读 [platform-baselines.md](references/platform-baselines.md) 与 [report-and-handoff.md](references/report-and-handoff.md)：
- **短篇重点拆**：情绪热度排行、高频题材/设定、主力篇幅区间、前 3 句开头模式、结局偏好（HE/BE/开放式）、标题与导语公式、风口预警（正在爆发 / 即将起风 / 即将饱和）。
- **长篇重点拆**：题材热度与趋势、新题材 / 新金手指 / 新噱头三级甄别、新人物/新切入点提取、字数与更新节奏、书名与标签热词。
- 完成 **`选题简报.md`**：输出 2–3 个按可行性排序的推荐选题，每条走完四步漏斗（能爆假设 → 市场验证 → 差异化脑洞切口 → 可行性+风险+最小验证动作），并填好**下游写作接口块**。

### 4. 运行质量门校验与下游交接

交付前运行脚本核验防幻觉规则与交接字段完整性：

```text
python <skill-dir>/scripts/validate_scan.py --dir <本次扫榜目录>
```

校验通过后，将 `选题简报.md`（及 `扫榜报告.md`）按推荐赛道直接交接给下游：
- **5 万字以内短篇网文 / 微短剧向文本** → 交接给 **`webnovel-short-studio`**（自动对接体量模板 `flash/microdrama`、推进类型与引号规范）。
- **AI 短剧 / AI 漫剧 / 沙雕短剧剧本** → 交接给 **`ai-drama-script-studio`**（自动对接剧种模板 `ai-drama/comic-drama/shadiao`、目标制作后端 `minimax-h3/jimeng`、热评雷区与红果 40× 规则）。
- **厚重长篇 / 出版级精品** → 交接给 **`story-world-architect` → `story-outline-architect` → `story-prose-writer`** 三件套。
